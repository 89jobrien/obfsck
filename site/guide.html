What it does

- Replaces secrets with labeled tokens (for example [REDACTED-AWS-KEY]) - Obfuscates identifiers with stable mappings (same input => same token) - Supports privacy levels based on how aggressive redaction should be

Obfuscation levels

- Minimal: secret pattern redaction only - Standard: adds IP, email, container ID, user, and PII obfuscation - Paranoid: adds path, hostname, and high-entropy token redaction Path obfuscation supports Unix, Windows drive paths, and UNC paths. Sensitive system paths are preserved. Preserved path segments include common roots like home, usr, etc, windows, users, and programdata.

What each level redacts

Pattern categoryminimalstandardparanoid
Prefixed API keys & tokens (AWS, GitHub, Stripe, …)yesyesyes
Generic password = … / api_key = … in source———
IPs, emails, container IDs, usernames—yesyes
PII (names, SSN, phone, credit card)—yesyes
Paths, hostnames, high-entropy strings——yes
Paranoid-only PII (IBAN, passport, DL)——yes

standard is the privacy-forward default for sharing logs externally. minimal is safe for internal tooling where structural identifiers are useful.

Generic keyword-anchored patterns (password = …, api_key = …) live in the code_context group in config/secrets.yaml, which is enabled: false because they false-positive heavily on source code. Nothing of that shape is redacted at any level unless you enable that group in a custom config — which is the right setting when scanning .env files, config dumps, or log output rather than code.

obfsck CLI

Redact secrets and PII from a file or stdin.

echo "key=sk-ant-api03-ABCDEF..." | obfsck redact
# Stdin -> stdout (default level: minimal — secrets only)
$ echo "key=sk-ant-api03-ABCDEF..." | obfsck redact

# File input
obfsck redact path/to/logfile.txt

# Write to output file
obfsck redact input.txt --output redacted.txt

# Increase level
obfsck redact input.txt --level standard   # + IPs, emails, usernames, PII
obfsck redact input.txt --level paranoid   # + paths, hostnames, high-entropy

# Audit mode — report findings to stderr while writing redacted output
obfsck redact input.txt --audit

# Custom secrets config (REPLACES the bundled pattern set)
obfsck redact input.txt --config ~/.config/obfsck/secrets.yaml

obfsck scan (pre-commit)

Scans a unified diff for secrets using both obfsck patterns and gitleaks.

git diff --staged | obfsck scan
# Pipe a diff
$ git diff --staged | obfsck scan

# Or let scan capture the staged diff itself
obfsck scan --staged

# Skip gitleaks (obfsck patterns only)
obfsck scan --staged --no-gitleaks

# Require gitleaks instead of skipping it when unavailable
obfsck scan --staged --require-gitleaks

# Set obfuscation level
obfsck scan --staged --level standard

Exit codes: 0 clean, 1 findings reported, 2 scanner or git failure.

Pre-commit hook

The repository ships just scan-diff, which pipes the staged diff through obfsck scan --no-gitleaks and then runs gitleaks protect --staged. To wire it up directly:

git diff --staged | obfsck scan --level minimal
#!/bin/sh
$ git diff --staged | obfsck scan --level minimal

Or use --staged mode:

obfsck scan --staged --level minimal
#!/bin/sh
$ obfsck scan --staged --level minimal

The standalone scan binary still works and forwards here, but it prints a deprecation warning on every run. Prefer obfsck scan.

The allowlist at ~/.config/obfsck/allowlist (one entry per line) skips known false positives like test fixtures.

obfsck:ignore

Fixtures and examples routinely contain credential-shaped strings that are not secrets. Mark the line and both obfsck redact and obfsck scan leave it alone:

obfsck:ignore
# Trailing marker — suppresses its own line
let key = "AKIAIOSFODNN7EXAMPLE"; // obfsck:ignore

# Standalone marker — suppresses the line below it
#[obfsck:ignore]
AKIAIOSFODNN7EXAMPLE

The marker is matched as a bare token anywhere in the line, so #, //, or no comment sigil all work, and obfsck: ignore is equivalent. A word boundary is required after ignore — obfsck:ignored is prose and does not suppress.

Only a line with no other text beside the marker suppresses the line below it. A trailing marker suppresses its own line and stops there, so marking one fixture line cannot quietly exempt the next.

In a diff, a marker on a context line governs the added line replacing the line below it. A marker that is itself being removed is not honoured.

Use the allowlist instead when a value should be skipped everywhere, rather than on one line. See README.md for the full marker rules.

Alert Analyzer

Fetches alerts from Loki or VictoriaLogs, obfuscates them, and sends to an LLM for analysis. Behind the analyzer feature flag.

cargo run --bin obfsck -- analyze --last 1h --limit 5 --dry-run
$ cargo run --bin obfsck -- analyze --last 1h --limit 5 --dry-run

The standalone redact and analyzer binaries are deprecated compatibility aliases. New scripts should use obfsck redact and obfsck analyze. Common options:

-c, --config <path>            Configuration file path
-p, --priority <priority>      Filter by priority
-l, --last <duration>          Time range to query [default: 1h]
-n, --limit <n>                Maximum number of alerts [default: 5]
-d, --dry-run                  Skip LLM analysis, show obfuscated prompt
-s, --store                    Store the generated analysis
-v, --verbose                  Enable verbose output
-j, --json                     Emit JSON output
    --loki-url <url>            Override the Loki endpoint
    --victorialogs-url <url>    Override the VictoriaLogs endpoint
-b, --backend <backend>        Log backend (loki|vm|victorialogs)

Custom config

The bundled config/secrets.yaml covers common secret patterns grouped by category (ai_apis, cloud, pii, paranoid, etc.). Each group supports:

groups:
  my_group:
    enabled: true
    min_level: standard   # omit to apply at all levels
    patterns:
      - name: my_token
        pattern: '\bTOK_[A-Za-z0-9]{32}\b'
        label: MY-TOKEN
        paranoid_only: false  # true = only fires at paranoid

Lookup order: --config flag -> ~/.config/obfsck/secrets.yaml -> bundled config. The selected YAML replaces the bundled pattern set; it is not merged on top of it. Obfuscator::with_pattern_set is documented as “Replaces the bundled secret patterns used by this obfuscator.”

This is a replacement, not an overlay. Verified: with a custom config that defines a single unrelated pattern, aws_key=AKIA… is passed through unredacted, whereas with the bundled config it becomes [REDACTED-AWS-KEY]. If you supply a custom config, re-declare every pattern you still want.

Public API

use obfsck::{obfuscate_text, ObfuscationLevel, Obfuscator};

// One-shot function
let (redacted, map) = obfuscate_text(text, ObfuscationLevel::Standard);

// Stateful obfuscator with allowlist
let mut obfuscator = Obfuscator::new(ObfuscationLevel::Standard)
    .with_allowlist(vec!["10.0.0.1".into()]);
let redacted = obfuscator.obfuscate(text);

Exports: - obfuscate_text(text, level) -> (String, ObfuscationMapExport) - obfuscate_alert(output, fields, level) -> (Option<String>, Option<HashMap<String, String>>, ObfuscationMapExport) - Obfuscator::new(level) — stateful, also supports .with_pii(), .with_pattern_set(), and reads back .level() / .mapping() - Allowlist::new(entries) — exact values and glob patterns preserved verbatim - ObfuscationLevel::parse("minimal|standard|paranoid") - PatternSet::bundled() — compile bundled secret definitions - PatternSet::from_config(config) — compile enabled runtime groups and custom patterns - PatternSet::{patterns, diagnostics, is_empty} — inspect compiled patterns and errors - Pattern::{name, group, expression, label, min_level, regex, applies_at} — inspect metadata and gating - PatternCompileError::{name, group, message} — inspect invalid-pattern diagnostics - SECRET_PATTERN_DEFS and secret_pattern_errors() — the definitions baked in by build.rs, and any that failed to compile

Feature-gated modules (api, analyzer, clients, mcp, schema, logging, cli, scan) require the analyzer feature, which is on by default. adapters, ports, patterns, helpers, and suppression are always available.

Example output

Before: event_id=evt-001 user=alice src=10.1.1.5 dst=198.51.100.10
        email=alice@corp.example path=/var/lib/app/environment.json

After:  event_id=evt-001 user=[USER-1] src=[IP-INTERNAL-1]
        dst=[IP-EXTERNAL-1] email=[EMAIL-1] path=/var/lib/app/[FILE].json

Filenames are only redacted when the stem is longer than three characters, so env.json survives the path pass and is then caught by the hostname pass as [HOST-1] instead. Lengthen the stem, or accept [HOST-1], if that surprises you.
